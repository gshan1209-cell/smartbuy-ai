# SmartBuy AI 情境側欄

## 執行原則

- 先確認畫面所屬 Layout、路由、登入狀態、角色與既有導覽，避免把所有頁面共用成同一組功能。
- 共用側欄元件只負責外框、寬度、收合、焦點狀態、active 狀態、Tooltip、ARIA 標籤與 RWD。
- 由路由或頁面上下文提供 `title`、分組標題與專屬連結；不得把另一個畫面的操作項目硬套到目前頁面。
- 桌機使用固定側欄，平板提供可收合側欄，手機使用抽屜或底部導覽；手機不應讓固定側欄壓縮內容。
- 連結須使用既有路由與正式權限判斷。管理入口只能在前後端權限都允許時顯示，未知角色採最低權限。
- 不得以側欄改動取代既有 API、資料來源、頁面功能或角色守衛。

## 實作步驟

1. 盤點目前 Layout、路由、既有 Sidebar／Drawer／BottomNav 與版型偏好。
2. 定義共用 shell 的 CSS 變數、側欄寬度、收合狀態、內容偏移與手機覆寫規則。
3. 建立頁面上下文設定，為每個受影響路由指定自己的標題、分組與操作連結。
4. 以 `NavLink` 或既有路由元件渲染 active 狀態，所有圖示按鈕提供可理解的 `aria-label` 與 `title`。
5. 驗證 Desktop、Tablet、Mobile 三種版型，並確認抽屜、底部導覽、鍵盤焦點與管理入口沒有回歸。

## 驗收條件

- 每個畫面的側欄內容符合該畫面的工作情境，沒有無關的共用清單。
- 桌機／平板／手機切換後，內容不被側欄遮擋，收合與抽屜操作可用。
- 未登入與不同角色看到的入口符合既有權限規則。
- Build、既有測試與路由回歸驗證通過，並留下可重現結果。
